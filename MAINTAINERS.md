# Maintainers

## Current roles

| Role | Holder | Responsibilities |
| --- | --- | --- |
| Founding maintainer | Repository owner | Product direction, review, releases, and contributor support |
| Repository administrator | Repository owner | Access control, security settings, and ownership verification |

The public repository owner is the authoritative identity for these roles.
Maintainer-verification requests must be submitted by an account with
repository write or administrator access.

## Contact

- Public bug reports and feature proposals: GitHub issues.
- Private vulnerability reports:
  [GitHub private vulnerability reporting](../../security/advisories/new).
- Participation concerns: the private route described in `CODE_OF_CONDUCT.md`.

## Maintenance expectations

Maintainers:

- Review changes against the offline, file-safety, and idle-work boundaries.
- Require green build, contract, smoke, and release-audit evidence as applicable.
- Keep release and security status accurate.
- Recuse themselves when a conflict of interest could affect a decision.
- Remove access that is no longer needed.

New maintainers are added through a pull request updating this file after the
governance process in `GOVERNANCE.md`.
